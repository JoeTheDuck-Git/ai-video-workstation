# reference-guided-cut-planner

Status: project-local draft; no autonomous analysis/render service is implemented.

Use the single two-stage [draft-package question](../video-delivery-qc/references/export-choices.md#draft-package-choice): yes/no, then Jianying / CapCut / both. Keep unanswered choices pending; record each selected product’s platform/version, support and validation status independently. Both exporters are currently unsupported; do not substitute movie rendering or claim that a renamed package supports both products.

## Target duration before selecting content

For each new editing job, first ask the user “這次影片希望剪到幾分鐘以內，還是以原片長度為主？” Offer “3 分鐘內”, “5 分鐘內”, “8 分鐘內”, “以原片長度為主”, and a way to enter another duration. With `request_user_input_async`, include all four selectable choices and its built-in free-text field for other durations; explain that users can type another length. Do not insert a nonfunctional “Other” choice when free-text is built in. An explicit duration already given for this job satisfies the question. A preselected option or elapsed time does not select the duration.

For “以原片長度為主”, record `duration_policy: source_led` and `max_duration_seconds: null` in the task request (not in a bound renderer map). Preserve the substantive narrative, examples, qualifications and protected phrases; remove evidenced failed takes, accidental repeats and excessive gaps without forcing a shorter summary. This is not an exact-length target: do not pad, freeze or slow footage to restore the source duration. Report source and estimated/actual edited lengths and the removal reasons. Do not apply the secondary-content deletion policy merely to shorten a source-led edit.

Treat “within” as a maximum for the whole export, including introductions, protected phrases, transitions and the natural ending. Save the chosen maximum in seconds per job. Ask briefly if a custom entry is ambiguous or not a positive duration. Do not pad a short source to fill a 5- or 8-minute limit. Before the answer, proceed with source inspection/transcription, but treat any existing content budget as provisional and do not finalize duration-dependent selections or render. Use the answer to budget narrative beats and choose content before tuning pauses; preserve full words, qualifiers, protected phrases and closing motion. If the selected maximum cannot fit essential/protected content, present the concrete tradeoff rather than silently cutting it or speeding up the whole film.

Ask duration and transcript-preview preference together when both are unknown, to avoid successive questionnaires. If either question is already pending or answered, ask only for the missing item; keep earlier pending answers associated with the same job. Confirm export resolution when ready to render. A later duration change requires updating the source map, estimated transcript timeline and plan version before rendering. Do not reuse another job’s time budget. For a numeric limit, verify actual exported duration against the chosen maximum; for source-led edits, verify content preservation and explain the duration difference.

## Optional transcript preview before rendering

For this user's new editing jobs, offer a chat option box before starting a video render: “影片渲染前，要先看 AI 預計保留的逐字稿與剪輯時間軸嗎？” Choices: “先看逐字稿＋時間軸（推薦）” and “直接渲染影片”. Use `request_user_input_async` when available; otherwise ask the same concise question in chat. Reuse an explicit choice for the current job; “直接剪好／不用看草稿” selects direct rendering, while “先看計畫／逐字稿” selects review. Do not ask again merely because an ordinary edit was authorized. This option adds a lightweight review route; it does not make every cut require approval.

While the choice is pending, continue authorized source inspection, cached transcript reuse and draft planning, but do not launch the render. A preselected option or elapsed time is not the user's choice. In review mode, prepare and show the concrete transcript/timeline before asking whether to render it or change it; do not render until the user requests proceeding. In direct mode, retain the same evidence and source map internally and proceed under existing authorization, subject to the selected export resolution and normal checks.

The review draft must include:

- Source identity and plan version, original duration, estimated edited duration and a brief narrative order. Mark all output timecodes as planned, not measured final media times.
- A readable table with stable sentence/clip IDs, planned edited start/end, original source start/end, actual retained spoken wording, and notes for protected phrases, joins or uncertain recognition. Put the retained speech in edited playback order so the user can read the proposed film from beginning to end. This is the proposed edit transcript, not merely an unedited transcript dump or a rewritten narration script.
- A compact deletion/change list with source intervals, deleted wording or clearly labelled summaries, and reasons such as failed take, redundancy or long pause. Keep the source transcript available for comparison. Do not silently remove disfluencies from displayed retained text while leaving them in the edit.
- Estimated sentence gaps and protected-phrase status, with uncertainty clearly marked. Text review can establish selection/order and meaning; it cannot certify audible breathing, facial motion, sync or the absence of missed repeats. Preserve post-render spoken review and technical QC.

Derive the displayed timeline and the renderer's plan from one source-to-output map, including playback rate and planned gaps. Do not estimate source timecodes by character count or invent words. With only coarse ASR timing, label the precision/uncertainty and leave unsafe executable boundaries unresolved. Reuse cached local source transcripts to avoid unnecessary full retranscription; do not promise an exact turnaround or skip needed evidence. Save the review mode and plan version per job. User changes update that map and estimated duration; prior approval and previews do not silently apply to a changed plan. No video render is needed to generate this draft, and a text draft is not a playable-video preview.

Before this user's final render/export, follow the [export resolution choice](../video-delivery-qc/SKILL.md#this-users-export-choice): offer selectable 480p (草稿) / 720p / 1080p / 4K / 原始解析度 unless already explicitly selected for this export. Keep agreed lightweight previews during skill tuning; a capability question alone does not request a higher-resolution render.

Before committing this user's talking-head sentence joins, apply the [sentence-pacing rules](../spoken-edit-review/SKILL.md#sentence-pacing): initially aim for 0.12–0.18 seconds between actual audible sentence end/onset, using clean original moving handles and natural room tone. Complete speech and smooth motion outrank the numeric target. Do not add frozen frames or cut phonemes to meet it. Record achieved gaps and justified exceptions in the cut plan, then review rendered joins; this range is not a substitute for listening or a rule for all within-sentence pauses.

Also apply the [source-boundary and final-word gate](../spoken-edit-review/SKILL.md#source-boundary-and-final-word-gate) before rendering: reject incoming fragments of the previous sentence and inspect audio beyond the proposed final out-point. Preserve complete farewell speech before adding natural closing room; ASR word-end timestamps alone are insufficient.

For talking-head rough cuts, run [spoken-edit-review](../spoken-edit-review/SKILL.md) on the exported speech before claiming editorial completion. Preserve its open defects and full-track coverage record separately from map/export validation. A clean ASR sentence can conceal a retake inside a retained clip.

Before selecting cuts, read the user's [protected phrases](../../docs/reference-editing-lab/protected-phrases.json) when present. Prompt users once that they may protect introductions, recurring phrases and CTAs; reuse an existing list rather than asking repeatedly. Approximate wording requires semantic/source-audio matching, not exact transcript search. Protect each requested unit's complete natural take and intended position; generic redundancy, low-information and CTA-removal heuristics cannot override it. Record source/output intervals and missing units. If the hard duration cannot fit protected content after shortening unprotected material, report the conflict instead of silently removing protected speech. Do not fabricate absent dialogue.

Read [the local editing prompt](../../docs/reference-editing-lab/EDITING_PROMPT.md) and [version/conflict notes](../../docs/reference-editing-lab/INTEGRATION.md) before upstream references. Route source trim/splice/reorder to general-video + hyperframes-core; talking-head-recut is only unchanged continuous footage plus overlays. Use the current job’s explicit duration limit; do not impose a default length or pad shorter material. Budget the narrative before selecting segments; under an explicit shorter-duration brief, remove semantic redundancy and secondary material as well as mistakes. Under source-led duration, preserve substantive content as specified above. Preserve qualifiers, negation and factual meaning. Policy-authorized or individually reviewed decisions feed one deterministic source-to-timeline map; do not ask for each routine cut again. Record policy authorization honestly, never as fabricated per-cut human review. Missing source/word timing blocks executable speech cuts. Rough-cut per-boundary QC precedes effects. Block unverified footage-sifter FCPXML export.

Read [the shared contract](../../docs/reference-editing-lab/CONTRACT.md). Obtain new-media inventory/selects from existing `footage-sifter`; do not invent another selection engine or move originals. Pin the reviewed style profile version. Unapproved rules may inform clearly marked alternatives, never an approved render plan.

Match each narrative beat to actual evidence-backed source intervals. Preserve essential speech and factual sequence; reject a visually similar clip that says or demonstrates the wrong thing. Explain match rationale, gaps, alternatives, and reused source ranges. Match style principles, not every reference cut point.

Produce neutral source-in/source-out, track, destination ticks, speed ratio, narrative role, rule IDs and effect requests. Use exact rational time conversion; VFR media uses presentation timestamps, not `frame/fps`. For speed ramps, unknown effects, layered transitions, or unsupported crop/retime, leave a manual/candidate item with explicit fallback; a named effect is not proof of render support. Do not label support verified without adapter/version and test evidence.

Run the draft validator described in CONTRACT.md. Return the readable shot plan beside JSON and a list of review blockers. When the current user authorizes a first playable rough cut, use the confirmed job settings and a verified local adapter; do not infer upload or publication permission. Plan-only requests remain plan-only. Ask only for ambiguous evidence, changes of meaning, conflicting essential facts or an unavoidable duration tradeoff. A missing adapter is a capability blocker, not a reason to request the same editing permission again. The current neutral schema remains a draft if it cannot represent policy authorization; do not fake approval fields. HyperFrames owns final rendering after an explicitly scoped handoff; Canvas/Manim create only requested supplemental assets. Caption Doctor cleans locked master captions, Subtitle Translator handles optional languages, existing video-delivery-qc checks the exported artifact.

No CapCut/剪映 exporter is included. Resolve/OTIO are unverified future adapters, not delivered capabilities. Keep unsupported features unresolved rather than silently dropping them. Batch output creates separate job IDs/profile pins and non-destructive deliverable paths per film; this skill is not a batch worker implementation.

## Independent post-export acceptance

After the authorized export, execute the [independent review packet, actual sub-agent dispatch and gate](../spoken-edit-review/references/independent-review.md). The editor supplies source/export/map, anomaly evidence and version hashes; a different reviewer checks all retained interiors and boundaries. Keep technical, ASR and real audio-review coverage separate. Final pass requires the gate, not the renderer exit code. If tools cannot listen or an issue is unresolved, deliver only a clearly labelled authorized review draft. Do not rerender merely to satisfy review when the user requested inspection only.

## Before executable cuts

Use [source-review.md](../spoken-edit-review/references/source-review.md): raw ASR plus pause/timing/restart candidates, new independent blind reviewer then comparison, source-review authorization, and `scripts/lab/plan-spoken-cut.py` before an executable map. Do not turn >=0.90 textual similarity into auto deletion. Always preserve fillers/false starts in raw evidence and complete source-word confidence. This is a required entry for both modes; post-export gate revalidates it. For an authorized evidence-assisted preview, use [preview-mode.md](../spoken-edit-review/references/preview-mode.md) and `--mode preview` to authorize candidate boundaries with independent evidence review. Mark limitations explicitly; preview authorization cannot become final approval.
